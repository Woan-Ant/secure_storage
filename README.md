# Secure Storage

[![style: very good analysis][very_good_analysis_badge]][very_good_analysis_link]
[![License: MIT][license_badge]][license_link]

Android · iOS · Web · macOS · Windows · Linux

Encrypted key-value storage for Flutter, layering [Hive CE][hive_ce_link] boxes
on top of [Flutter Secure Storage][fss_link].

Hive is fast but stores its boxes as plain files. Flutter Secure Storage is
backed by the platform keystore but is meant for small secrets, not bulk data.
This package combines them: your values live in Hive boxes, and each encrypted
box gets an AES key that is generated by Hive and held in the keystore under the
box name. The key never touches the box file it protects.

## Installation 💻

**❗ In order to start using Secure Storage you must have the
[Flutter SDK][flutter_install_link] installed on your machine.**

```sh
flutter pub add secure_storage
```

### Platform setup

Runs on all six Flutter platforms. The requirements come from
`flutter_secure_storage`, not from this package:

| Platform | Requirement                                                       |
| -------- | ----------------------------------------------------------------- |
| Android  | `minSdk = 24`, and `compileSdk = 37` for `flutter_secure_storage` 11 |
| iOS      | Deployment target 13.0                                            |
| macOS    | Deployment target 10.15, with the Keychain Sharing capability     |
| Web      | Boxes live in IndexedDB; `listUnencryptedKeys` returns `[]`       |

On Android, set both in `android/app/build.gradle.kts`:

```kotlin
android {
    compileSdk = 37
    defaultConfig {
        minSdk = 24
    }
}
```

## Quick start 🚀

```dart
import 'package:flutter/foundation.dart';
import 'package:get_it/get_it.dart';
import 'package:path_provider/path_provider.dart';
import 'package:secure_storage/secure_storage.dart';

final sl = GetIt.instance;

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();

  // This package does not depend on path_provider, so that it can also run on
  // web. Resolving the directory is your app's job — on web Hive uses
  // IndexedDB and there is no directory at all.
  final storagePath = kIsWeb
      ? null
      : (await getApplicationDocumentsDirectory()).path;

  initSecureStorageFeature(sl: sl, storagePath: storagePath);

  final storage = sl<SecureStorage>();

  await storage.storeData<String>(
    data: 'a-jwt-token',
    param: ParamStoreData(
      boxName: 'auth',
      dataKey: 'token',
      encrypted: true,
    ),
  );

  final token = await storage.getData<String>(
    param: ParamGetData(boxName: 'auth', dataKey: 'token'),
  );
}
```

## Two ways to use it

### The service — throws

`SecureStorage` is the plain service. Every operation throws a typed
`AppException` on failure.

```dart
try {
  final token = await storage.getData<String>(param: param);
} on DataDoesNotExistException {
  // nothing stored under that box and key
} on HiveOpenBoxException {
  // the box exists but could not be opened
}
```

### The repository and use cases — return `Either`

`StorageRepository` wraps the service and converts every exception into a
`Failure` value, so nothing throws. The `Either` is [dartz][dartz_link]'s, and
this package re-exports `Either`, `Left` and `Right` so you do not need to add
dartz to your own pubspec:

```dart
final result = await sl<GetDataUseCase>()(
  param: ParamGetData(boxName: 'auth', dataKey: 'token'),
);

result.fold(
  (failure) => print('${failure.prefix}-${failure.code}: ${failure.message}'),
  (token) => print(token),
);
```

The six use cases are `CheckDataUseCase`, `StoreDataUseCase`, `GetDataUseCase`,
`DeleteDataUseCase`, `ListEncryptedKeysUseCase` and `ListUnencryptedKeysUseCase`.

## How keys are addressed 🔑

Every parameter object normalises what you pass in: spaces become underscores,
everything is lower cased, and the data key is namespaced with the box name.

```dart
ParamGetData(boxName: 'My Box', dataKey: 'Access Token');
// boxName: 'my_box'
// dataKey: 'my_box_access_token'
```

Namespacing means two boxes can hold the same logical key without colliding. In
debug builds, empty segments and anything outside letters, digits, spaces and
underscores trip an assertion.

## Encryption 🔒

`encrypted` on `ParamStoreData` only takes effect the first time a box is
created:

```dart
// Creates an encrypted box.
await storage.storeData(data: v, param: ParamStoreData(
  boxName: 'auth', dataKey: 'token', encrypted: true,
));

// The box already exists, so it stays encrypted. `encrypted: false` is ignored
// rather than silently rewriting the box in the clear.
await storage.storeData(data: v, param: ParamStoreData(
  boxName: 'auth', dataKey: 'refresh',
));
```

Use `isDataExist` to find out which mode a box is in. It returns
`encrypted: null` when the box does not exist at all, which is how the write
path distinguishes "creating a box" from "adding to one".

Deleting the last entry in a box deletes the box from disk and, for an encrypted
box, removes its key from the keystore — so no orphaned keys accumulate.

> **⚠️ `listEncryptedKeys` returns live encryption keys.** It exists for
> diagnostics. Never log, display or transmit its values.

## Storing your own types 📦

Register a Hive `TypeAdapter` through the init callback. It takes a callback
rather than a list so each adapter keeps its static type — Hive routes every
write through an adapter registered as `TypeAdapter<dynamic>`.

```dart
initSecureStorageFeature(
  sl: sl,
  storagePath: storagePath,
  registerAdapters: (hive) => hive.registerAdapter(UserModelAdapter()),
);
```

## Logging 🪵

Nothing is logged by default. Pass a logger to see what the package is doing:

```dart
initSecureStorageFeature(
  sl: sl,
  storagePath: storagePath,
  logger: const DebugPrintSecureStorageLogger(),
);
```

Implement `SecureStorageLogger` to forward to your app's own logger. The package
never puts encryption keys or stored values into its messages.

## Errors 🚨

Each failure carries a `prefix` identifying the subsystem and a `code` unique
within it.

| Prefix                   | Code  | Failure                   |
| ------------------------ | ----- | ------------------------- |
| `HIVE`                   | `001` | `HiveWriteFailure`        |
| `HIVE`                   | `002` | `HiveWipeFailure`         |
| `HIVE`                   | `003` | `HiveReadFailure`         |
| `HIVE`                   | `004` | `OpenFailure`             |
| `HIVE`                   | `005` | `CloseFailure`            |
| `HIVE`                   | `006` | `HiveDeleteBoxFailure`    |
| `HIVE`                   | `007` | `HiveDeleteDataFailure`   |
| `HIVE`                   | `008` | `HiveBoxNotEmptyFailure`  |
| `HIVE`                   | `009` | `BoxEncryptedFailure`     |
| `SECURE STORAGE`         | `001` | `DataDoesNotExistFailure` |
| `FLUTTER SECURE STORAGE` | `001` | `FSSWriteFailure`         |
| `FLUTTER SECURE STORAGE` | `002` | `FSSReadFailure`          |
| `FLUTTER SECURE STORAGE` | `003` | `FSSNotFoundFailure`      |
| `FLUTTER SECURE STORAGE` | `004` | `FSSDeleteFailure`        |

## Wiring it up yourself

`initSecureStorageFeature` is a convenience. If you do not use `get_it`, build
the pieces directly:

```dart
final storage = SecureStorageImpl(
  hiveInterface: myHiveInstance,
  fSS: const FlutterSecureStorage(),
  boxDirectoryPath: storagePath,
);
final repository = StorageRepositoryImpl(secureStorage: storage);
final getData = GetDataUseCase(storageRepository: repository);
```
